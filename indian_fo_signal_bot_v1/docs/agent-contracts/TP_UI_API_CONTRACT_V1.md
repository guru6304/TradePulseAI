## Transport, methods, and local authority

The API is the standard-library `DashboardRequestHandler`, with equivalent `/api/<resource>` and `/api/v1/<resource>` aliases. A trailing slash is removed before API dispatch. `HEAD` executes the same read handler and sends the same headers and computed content length as `GET`, but no body. API JSON uses UTF-8, `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`. An optional handler `evidence_scope` is added at the top level of **every** JSON response, including errors. See [server.py:102](../../server.py#L102), [server.py:221](../../server.py#L221), [server.py:1152](../../server.py#L1152).

Requests require one loopback `Host` matching the actual server port, a loopback client, no cross-site `Sec-Fetch-Site`, and either no `Origin` or the exact HTTP origin derived from `Host`. Failure is HTTP 403 with `status: "error"`, `reason_code: "LOCAL_SAME_ORIGIN_REQUIRED"`, and `message: string`. This is a local application, with no public multiuser authentication contract. The server factory restricts bind hosts to loopback. See [server.py:1351](../../server.py#L1351), [server.py:1438](../../server.py#L1438), [server.py:1455](../../server.py#L1455).

`GET`/`HEAD /api/scan` and its versioned alias return 405 `EXPLICIT_POST_REQUIRED` **before runtime initialization**. Unsupported POST resources return 405 `MethodNotAllowedError` before initialization. Unknown API reads return 404 `NotFoundError` before initialization. There is no order-placement route. `OPTIONS` on any API path returns 204 after the local request check; its advertised methods do not authorize an operation. See [server.py:1157](../../server.py#L1157), [server.py:1284](../../server.py#L1284), [server.py:1305](../../server.py#L1305).

Read handlers inspect retained facts; they do not call scanner acquisition, paper marking/filling, imports, enrichment or backtest execution. **Qualification:** a recognized read calls `_ensure_initialized()`. Cold initialization constructs the engine/store and can initialize persistence; `configure_server_runtime()` also follows the effective scheduler setting. Thus read-only handler behavior is not a guarantee that arbitrary cold configuration has no initialization writes or scheduler effects. H0 and offline clients require `ACTIVE_BROKER=paper_sim`, `TELEGRAM_DRY_RUN=true`, `ENABLE_BACKGROUND_SCHEDULER=false`, plus disposable fixture storage. See [server.py:216](../../server.py#L216), [server.py:1173](../../server.py#L1173), [server.py:1371](../../server.py#L1371).

## Ranking response and stable snapshot consumption

`GET opportunity-rankings` returns a distinct schema, not the ordinary `items` list envelope. Source: [rank_history.py:311](../../rank_history.py#L311), [opportunity_ranking.py:97](../../opportunity_ranking.py#L97).

| Field | JSON type / meaning |
|---|---|
| `status` | string: `RANKING_UNAVAILABLE_NO_DURABLE_SCAN`, `CURRENT_CANDIDATE_PRIORITY`, `STALE_OR_FUTURE_SNAPSHOT`, `ARCHIVED_DIFFERENT_RUNTIME_SCOPE`, `ARCHIVED_DIFFERENT_CODE`, or `ARCHIVED_NON_CURRENT_SCAN`; transport failures use separate error shapes. |
| `actionable` | literal false, including current candidate priority. |
| `scope` | object `{provider:string,data_mode:"LIVE"|"SIMULATED",segment:"NSE_EQUITY_INTRADAY",profile_digest:string}`. Runtime profile binds selection. |
| `as_of` | offset-qualified ISO string from **server** read clock. |
| `current_rows` | array of ranking rows only for current status; otherwise empty. |
| `historical_rows` | same requested retained page regardless of current/archive status; unavailable response empty. |
| `pagination` | `{offset:integer,limit:integer,total:integer}`, total <=512. This is **not** `total_count`. |
| `snapshot` | object described below, or null when no durable rank is available. |

Snapshot keys are `policy:string`, `rank_version:string` (SHA-256), `previous_rank_version:string|null`, `valid_until:string`, `evidence_scope:string`, `run_id:string`, `work_id:string`, `reference:string`, `scope:object`, `previous_snapshot:object|null`, `source_authenticity:"NOT_ESTABLISHED"`, `source_data_watermarks:string[]`, `source_data_watermark_count:integer`, `exclusions:object[]`, `exclusion_count:integer`, `removals:object[]`, `removal_count:integer`, `metadata_preview_limit:100`, and three booleans `exclusions_truncated`, `removals_truncated`, `source_data_watermarks_truncated`. These metadata arrays are **previews capped at 100**, independently of row pagination. Predecessor descriptor contains `schema_version`, `run_id`, `work_id`, `scope_digest`, `reference`, `payload_sha256`, `rank_version`, nullable `previous_rank_version`, `actionable:false`. Exclusions contain nullable candidate/symbol values and string `reason_code`; removals contain `opportunity_key`, `symbol`, integer `previous_rank`, `new_rank:null`, `reason_code`. See [rank_history.py:100](../../rank_history.py#L100), [rank_history.py:353](../../rank_history.py#L353).

Each row contains:

- Strings `opportunity_key` (SHA-256), `candidate_id`, `symbol`, `strategy_id`, `position_type`, `direction` LONG/SHORT, `source_data_watermark` (aware ISO candle **start**), `source_digest` (SHA-256), `priority_scope="QUALIFIED_SCANNER_CANDIDATE_ONLY"`.
- `instrument_identity:object` with provider, identifier, symbol, exchange NSE, segment NSE_EQUITY_INTRADAY, instrument_type EQ, is_index false. Additional identity keys remain source-defined; exact identity equality is required, not symbol-only matching.
- `score_components:{rule_quality:number,actual_target1_rr:number}`, `component_versions:{rule_quality:"EXISTING_EVALUATOR_V1",actual_target1_rr:"PRICE_LEVEL_GEOMETRY_V1"}`.
- `missing_components:string[]` currently RELATIVE_STRENGTH, SECTOR, REGIME, LIQUIDITY_DEPTH, OBSERVED_SPREAD, NET_EXECUTABLE_REWARD, EMPIRICAL_EDGE.
- `rank:integer` (1-based), `previous_rank:integer|null`, `rank_change_reason` NEWLY_QUALIFIED/SCORE_COMPONENT_CHANGED/RELATIVE_ORDER_CHANGED/UNCHANGED_PRIORITY, `component_changes` map from changed component to `{previous:number|null,current:number}`, `actionable:false`.

The policy is `CASH_QUALITY_ACTUAL_RR_DIRECTION_ONE_SYMBOL_V2`: quality descending, then actual gross target-1 R:R descending, then deterministic symbol/strategy/key ties, with one surviving setup per symbol. No client weighted score, confidence probability, sector data or contract-fitness score is supplied. [opportunity_ranking.py:119](../../opportunity_ranking.py#L119).

The first request may omit `run_id`, selecting newest committed scanner work in the runtime profile; later pages **must** pin its returned `snapshot.run_id`. Verify unchanged run/work/version/scope/reference/expiry/policy, total, contiguous ranks, unique opportunity/candidate/identity/symbol, and complete page lengths before exposing any page as a whole snapshot. Explicit `run_id` reads a retained run; it does not necessarily mean latest. No cursor is provided for ranking. Storage validates immutable scan inputs, evaluation, persisted signal links, predecessor, code and checksums; missing/corrupt latest evidence must not silently reveal an older current ranking. [rank_history.py:109](../../rank_history.py#L109), [rank_history.py:222](../../rank_history.py#L222), [rank_history.py:325](../../rank_history.py#L325).

Freshness is based on completed five-minute source candles, aware server time, same-day source, source close no later than scan reference and at most 60 seconds old. Snapshot `valid_until` is the earliest row watermark +5m+60s. A zero-row snapshot uses scan reference as expiry, so it is current only at that exact reference; a later read can be archived even though it validly records zero qualified setups. The internal stored ranking requires `ranking.as_of <= read_clock <= ranking.valid_until`; the HTTP projection exposes the scan time as `snapshot.reference` and the read clock as top-level `as_of`, with **no `snapshot.as_of` field**. UI latency reduces remaining lifetime; clients must clear expired current rows and selected prices. [opportunity_ranking.py:79](../../opportunity_ranking.py#L79), [opportunity_ranking.py:137](../../opportunity_ranking.py#L137), [opportunity_ranking.py:158](../../opportunity_ranking.py#L158).

## Errors consumers must preserve

There is no universal error DTO. Older lists generally use `{status:"error",error_type:"ValidationError"|"PersistenceError"|"PersistenceDisabledError",message:string}` with 400/503. Ranking invalid query is 400 `{status:"error",message:"Invalid ranking query."}`; integrity failure is 503 `{status:"RECONCILIATION_REQUIRED",message:...}`; unavailable storage is 503 `{status:"UNAVAILABLE",message:...}`. Signal reconciliation and some scan errors use 503 `RECONCILIATION_REQUIRED`. Cash-lineage missing run is HTTP 404 but may have body status `RECONCILIATION_REQUIRED`; missing batch returns 404 `NOT_FOUND`. Paper missing account is 404 `NOT_CONFIGURED`. Context uses `UNAVAILABLE` with `reason_code`; operational reads use reason codes. Error responses need not contain any rows, snapshot, accounting or prices. UI clients must clear failed/partial cached evidence rather than parse an error as an empty accepted result. Anchors: handlers in route table, [server.py:553](../../server.py#L553), [server.py:927](../../server.py#L927), [server.py:1006](../../server.py#L1006).
