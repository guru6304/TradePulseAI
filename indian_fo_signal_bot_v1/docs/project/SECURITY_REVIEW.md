## Threat model and acceptance boundary

The enabled design is a single-user loopback HTTP dashboard with paper-only simulation and explicit local actions. A foreign browser origin and a direct remote client are untrusted. A local process can intentionally use the CLI-style API; loopback is an exposure boundary, not user authentication or tenant authorization. Arbitrary same-user malware already able to read project files is outside the confidentiality guarantees established here. Local malformed clients and accidental unsafe startup configuration remain reliability/deployment concerns.

No remote, reverse-proxy or multiuser profile is accepted. `_loopback_bind_host`, `create_http_server` and `run_server` now reject nonloopback startup hosts; `_allow_local_request` separately checks each admitted request. These controls do not establish secure remote deployment. Fixture tests and source inspection do not certify OWASP compliance, absence of vulnerabilities, real market admission or release readiness. P1 below denotes a required engineering/release gate, not a demonstrated remote exploit.

## Current implementation and verification boundary

In `server.py`, `DashboardRequestHandler._json_body` is shared by `_handle_post_backtest` and `_context_body`. It rejects Transfer-Encoding, duplicate/missing Content-Length, nonpositive/oversized lengths, truncation, invalid UTF-8/JSON, duplicate keys, nonfinite numbers and nonobject bodies. The backtest limit remains 10 MiB; context remains 512 KiB. The existing downstream schema and cost checks remain in `_handle_post_backtest`; a permitted request still uses the explicit backtest route.

`DashboardRequestHandler.setup`, `parse_request`, `finish`, `_expire_input` and `_json_body` implement separate absolute header/body deadlines alongside socket inactivity limits. Production defaults are five seconds for each phase. Timers shut down the read side on expiration; explicit expiration checks reject partial input rather than allowing EOF to admit an incomplete request. Header timing starts before the request line and is canceled after parsing/cleanup. The body timer is canceled and the previous socket timeout restored in `finally`. `handle_one_request` handles expiration-related connection aborts while re-raising unrelated aborts. The trickle regressions use 150 ms fixture deadlines and bytes every 40 ms; they establish that continued input does not extend the deadline, not a production throughput budget.

`TradePulseThreadingHTTPServer.process_request` acquires a bounded semaphore before creating a worker; the production limit is 32. Its overload branch performs one read of at most 8 KiB with a 50 ms timeout, followed by a best-effort 503 with a 250 ms socket timeout and shutdown. It creates no additional worker or application dispatch. `process_request_thread` releases slots in `finally`, and thread-start failure releases the acquired slot. The two-worker fixture proves admission limits and recovery after held clients close or time out; it does not measure 32-worker load. Overload handling runs synchronously in the accept loop. Complete rejection delivery to every malformed/large peer and sustained throughput/SLO acceptance remain unmeasured.

`_loopback_bind_host` validates before configuration or binding in `run_server` and before binding in `create_http_server`, without hostname DNS resolution. `localhost` maps by policy to `127.0.0.1`; supported IPv6 loopback literals select an IPv6 server. `_dispatch_get_or_head` serves static GET/HEAD files and private-file 404s before runtime initialization. `_try_serve_approved_public_asset` maps `/`, case-insensitive `index.html` and `/public/index.html` aliases to the exact new `terminal.html` bundle. That entry uses local `terminal.css`/`terminal.js`; the old external-asset `index.html` remains a preserved developer reference. Static responses include no-referrer and frame denial. HTML CSP allows scripts/styles/connections/images/fonts only from self and disables objects, base changes, forms and framing, without unsafe-inline/unsafe-eval. Browser fixture evidence is recorded separately below; full UI parity, installation and whole-product security remain outside this acceptance.

## Concrete remaining source and evidence limits

`DashboardRequestHandler.do_POST` calls `_ensure_initialized` before route selection or body framing validation. A malformed backtest body or unsupported POST on a cold factory-created handler can therefore reach `configure_server_runtime` before rejection. `_dispatch_get_or_head` also initializes before rejecting unknown API routes, although static/private-file GET/HEAD paths now return first. The body-rejection tests inject an engine/scheduler, so their zero engine/store/backtest calls prove no tested dispatch effects in that initialized fixture; they do not prove that rejected cold requests cannot initialize configuration/storage. This remains an E02 item. No remote bypass or operational-store effect was executed to establish it.

The input timers and worker cap bound the selected input-wait paths. They do not impose a total execution deadline on admitted scans/backtests, cap the CPU or decoded-object cost of every allowed payload, or establish sustained-load availability. The worker tests use a two-slot subclass; real 32-slot saturation, large-peer overload delivery and latency/recovery SLOs still require measured acceptance.

The retained browser V3 passes did not settle timestamp interpretation across client timezones: formatting a `Date.parse` result in Asia/Kolkata does not itself ensure that a naive IST source string was parsed in IST, and comparisons must use the same timestamp interpretation. Root is correcting this separately. Fresh mixed-format/timezone and final browser/source-binding evidence is required before closing that UI correctness gate; the security receipt does not accept the whole UI.

Remote authentication/authorization remains gated by design. Dependency/SBOM/license and offline-install provenance, full recovery/operations, complete endpoint/log review and final release inspection remain open. These are material limits on E02 and release acceptance even though the three original targeted findings now have scoped implementation and PASS evidence.
